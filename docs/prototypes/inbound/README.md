# Inbound — ต้นแบบสำหรับทบทวนแบบ

ต้นแบบกดใช้งานได้ด้วยข้อมูลสมมติ เก็บในหน่วยความจำของแต่ละ tab; รีเฟรชหรือกดคืนข้อมูลจะเริ่มใหม่ ยังไม่ได้รวมเป็น Angular module และไม่มีการบันทึก stock จริง

จากโฟลเดอร์รากโปรเจกต์ รัน:

```powershell
.\.tools\node-v24.21.0-win-x64\node.exe scripts/preview-inbound.mjs
```

เปิด **http://127.0.0.1:4300** (ใช้ `node scripts/preview-inbound.mjs` ได้เมื่อมี Node ใน PATH). ฟอนต์ไทย/อังกฤษอ่านจาก dependencies ของ frontend; หากยังไม่ได้ติดตั้งจะใช้ system fallback. Server เปิดเฉพาะ loopback และเสิร์ฟเฉพาะไฟล์ที่กำหนดไว้

## ลองใช้งาน

1. Apo → `RP-261003-001`: รับกระดาษ 180 และสบู่ 60 ชิ้น ใส่ Lot/วันหมดอายุหลังวันที่ตัวอย่าง 3 ต.ค. 2026 → ตรวจ → จัดเก็บ. แบ่งรับหลายครั้งและจัดเก็บบางส่วนได้
2. `RP-261003-003`: ตรวจผ่าน 180 / ไม่ผ่าน 20 พร้อมเหตุผล → จัดเก็บ 180; เอกสารคงสถานะกักกัน
3. `RP-261003-004`: ตัวอย่างรับ/ตรวจแล้ว เหลือจัดเก็บ 48 ชิ้น
4. Squ: ปิด Lot/วันหมดอายุ/Inspection จึงรับแล้วจัดเก็บได้เลย; Mdr: ตัวอย่างโปรเจกต์ว่าง
5. “ตัวเลือกต้นแบบ”: เปลี่ยนบทบาท, จำลองโหลดไม่สำเร็จ, ส่งคำสั่งล่าสุดซ้ำ หรือคืนข้อมูลเริ่มต้น. Customer อ่านอย่างเดียว; Operator รับ/จัดเก็บได้ตามสมมติฐาน
6. “สร้างแผนรับเข้า”: สร้าง draft หนึ่ง SKU แล้วกดยืนยันแผน. แบบ Angular ขั้นถัดไปวางแผนรองรับ editor หลาย SKU

Barcode ตัวอย่างกระดาษ `8850000000011`; สแกนจะเลือกสินค้าและโฟกัสจำนวน ไม่เพิ่มยอดเอง. ลองบนมือถือได้ด้วย responsive viewport; server ไม่เปิดให้เครื่องอื่นในเครือข่ายโดยอัตโนมัติ

Role selector เป็นเพียงการจำลอง UI ไม่ใช่ระบบสิทธิ์จริง. REC-01/พื้นที่กักกันเป็นข้อความประกอบ workflow; เฉพาะตำแหน่ง STORAGE เป็น fixtures ที่เลือกจัดเก็บได้. คำสั่งที่อยู่ระหว่างหน่วงจำลองจะยกเลิกเมื่อออกจากฟอร์ม/รีเซ็ต; ไม่ใช่สัญญาสำหรับการยกเลิก transaction บน server จริง
