# ทดสอบ Module 1 ร่วมกัน

เปิด Docker Desktop, `docker compose up -d --wait`, Backend (`backend.cmd`) และ Angular (`wms.cmd`) แล้วเข้า http://localhost:4200

## 1. บัญชี Administrator

เปิด `.local/first-login.md` เพื่อดูชื่อผู้ใช้และรหัสผ่านชั่วคราวที่สร้างเฉพาะเครื่องนี้ เข้าระบบแล้วเปลี่ยนรหัสผ่านเป็นรหัสใหม่ 12–128 ตัวอักษร เก็บรหัสใหม่ไว้เอง

หลังเปลี่ยนต้องเห็น Apo, Squ, Mdr และเมนูจัดการระบบ ลอง refresh เพื่อยืนยันว่า Session ยังอยู่ เมื่อออกจากระบบ การเปิดลิงก์ workspace เดิมต้องกลับหน้า Login

## 2. สร้างผู้ใช้และ Role ต่อ Project

เข้า จัดการระบบ → ผู้ใช้งาน → เพิ่มผู้ใช้งาน กำหนดชื่อบัญชี ชื่อแสดง และรหัสผ่านชั่วคราว เลือก:

| Project | Role |
| --- | --- |
| Apo | Manager |
| Squ | Operator |
| Mdr | ไม่มอบสิทธิ์ |

เข้าบัญชีใหม่ในหน้าต่าง InPrivate ของ Edge เพื่อแยก Session จาก Admin ต้องถูกบังคับเปลี่ยนรหัสผ่านก่อน และเห็นเฉพาะ Apo/Squ พร้อม Role ต่างกัน ไม่เห็นเมนูจัดการระบบ

ลองค้นหา สลับ Project และ refresh ใน workspace ทั้งสองโปรเจกต์ จากนั้นลองเปิด `/workspace/mdr` ต้องไม่ได้รับอนุญาต

## 3. ตรวจ Permission

ในหน้าต่าง Admin เข้า สิทธิ์ตามบทบาท เอา `workspace.view` ของ Operator ออกแล้วบันทึก กลับหน้าต่างผู้ใช้และเปิด Squ อีกครั้ง ต้องเข้าพื้นที่ทำงานไม่ได้ ส่วน Apo ที่เป็น Manager ยังเข้าได้ จากนั้นคืน Permission ให้ Operator

ขณะนี้มี Permission เฉพาะการดูพื้นที่ทำงาน เมื่อพัฒนาโมดูลคลังจริงจึงเพิ่มสิทธิ์ดูหน้า/สร้าง/แก้ไข/ยืนยันของแต่ละโมดูล บริษัท Administrator ดูแลบัญชีและ Role ทั้งบริษัท โดยไม่ขึ้นกับสิทธิ์ Project

## 4. ดูแลบัญชี

- แก้ชื่อและ Role ของบัญชีทดสอบ แล้วตรวจผลหลังเปิดหน้าใหม่
- ปิดบัญชี ขณะผู้ใช้ยัง Login อยู่: request ถัดไปต้องไม่ได้รับสิทธิ์
- เปิดบัญชีอีกครั้งและรีเซ็ตรหัสผ่าน: Session เดิมต้องใช้ไม่ได้ รหัสใหม่ต้องเปลี่ยนเมื่อเข้าใช้
- เอา Project ออกทั้งหมด: ผู้ใช้ควรเห็นข้อความให้ติดต่อผู้ดูแล ไม่เห็น Project อื่น
- ระบบไม่ให้ Admin ปิดหรือลดสิทธิ์บัญชีตนเอง เพื่อไม่ให้สูญเสียผู้ดูแล

## 5. หน้าจอ

ทดลองทั้ง Desktop และจอกว้าง 360px ตรวจว่ากดปุ่มและกรอกฟอร์มได้ ไม่มีการเลื่อนแนวนอน ลองใช้ Tab และลิงก์ข้ามไปเนื้อหาหลัก

## ขอบเขตที่จบใน Module นี้

ระบบบัญชีและสิทธิ์ใช้ PostgreSQL จริง ไม่มี public signup, อีเมล reset, จัดการ Project หรือหน้ารับเข้า/จ่ายสินค้า ยังใช้เซิร์ฟเวอร์พัฒนาที่เครื่องนี้ การติดตั้ง production และ HTTPS เป็นงาน deployment แยกต่างหาก

## การดูแลข้อมูล local

`docker compose stop` หยุดฐานข้อมูลโดยเก็บข้อมูลไว้ และ `docker compose up -d --wait` เปิดกลับ ห้ามใช้ `docker compose down -v` ถ้าต้องการเก็บข้อมูล เพราะจะลบ volume
บัญชีที่สร้างผ่าน UI เป็นข้อมูลจริงใน local DB ทดสอบอัตโนมัติใช้ schema แยกและไม่เปลี่ยนบัญชีของคุณ

## ผลตรวจสอบก่อนส่งให้ลอง

ผ่าน Backend integration 11 tests, Frontend 15 tests และ Edge end-to-end 8 flows พร้อม build ทั้งสองส่วน ตรวจหน้าจอ Desktop/360px และแก้ผล code review แล้ว
Browser tests ครอบคลุมบัญชีจริง Role ต่อ Project การบังคับเปลี่ยนรหัสผ่าน การปิดบัญชี สร้าง/แก้ไข/รีเซ็ตผ่าน UI และออกจากระบบล้มเหลวแล้วลองใหม่

## หมายเหตุสำหรับพัฒนาต่อ

Login throttling อยู่ใน API process เดียว เหมาะกับการรันหนึ่ง instance ในขอบเขตนี้ ถ้าเพิ่มหลาย instance ให้ย้าย counter ไป shared storage
Backend ใช้ Multer 2.4.0 override เพื่อแก้ dependency ที่ Nest pin ไว้ ตรวจทบทวน override เมื่ออัปเดต Nest; ไม่ได้เปิด upload route ใน Module 1
